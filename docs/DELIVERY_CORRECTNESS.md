## 성공과 불확실성

발행 성공은 원본 메시지의 영속화 확인을 요구한다. 예약된 ID만으로 성공을 반환하지 않는다.
응답 유실 뒤 같은 client_key로 재시도하면 저장 원본을 확인해 같은 ID로 복구한다.
저장 여부를 확인할 수 없으면 재시도 가능한 오류로 알린다. 불확실성을 새 ID 발행으로 덮지 않는다.
중복 제거 창 이후에는 기존과 같이 새 발행이 될 수 있으므로, 오류를 받은 클라이언트가 새 client_key를 만들어 즉시 재발행해서는 안 된다.

## 수신 확인과 업무 완료

| 응답 | expects:reply의 최종 답 | expects:ack의 수신 확인 | 수락한 업무의 완료 |
|---|---|---|---|
| ack | 아니오 | 예 | 아니오 |
| in-progress 또는 상태 없는 report | 아니오 | 아니오 | 아니오 |
| reply / 최종 report | 예 | 예 | 예 |

로컬·원격 요청 대기는 ACK를 소비하되 최종 답을 계속 기다린다.
데몬은 원본의 expects를 기준으로 미응답을 판정한다. 요청에 ACK만 남기고 실행체가 종료되면 실패 보고 대상이다.
진행 보고나 발행 거부는 수락한 업무의 완료를 만들지 않는다. 수신 확인·완료 기록은 해당 메시지의 영속화 이후에만 반영한다.
공유 프로토콜 crate의 판정 함수로 어댑터들의 의미를 통일한다. 와이어 필드 변경은 없다.

## 권한 회수

원격 MCP는 바인딩된 도구마다 현재 조직 소속과 채널 grant를 검사한다.
대기 수신도 소비·반환 직전에 검사한다. 회수 시 바인딩과 수신 소유권을 해제하고 권한 오류를 반환한다.
이미 가져왔지만 반환하지 않은 메시지는 소비 확정하지 않고, 권한 있는 수신자에게 재전달되도록 돌려놓는다.
웹 대화의 자동 주입 지원 여부와 이 인가 규칙은 별개다.

## 검증 범위

회귀는 캐시 유지 중 권한 회수, 대기 중 회수와 메시지 보존, 저장 전후 중단과 동일 키 복구,
ACK→최종 답, ACK→실행체 종료, 진행 보고→이탈, 발행 거부와 정상 완료를 검증한다.
호스트 앱의 자동 주입 실기는 별도 사용자 환경에서 확인한다.
