# 릴리스 절차

## 실행 순서

1. 버전·릴리스 노트·잠금 파일을 포함한 후보 커밋을 main에 푸시한다.
2. 그 정확한 SHA의 3 OS CI와 무인 환경 회귀가 모두 성공했는지 확인한다. 이전 커밋의 성공이나 실행 중인 검사를 대신 사용하지 않는다.
3. 운영 측 검증 절차를 통과한 뒤 버전 태그를 생성하고 그 태그에서 release 워크플로를 명시적으로 실행한다. 태그 push만으로 릴리스하지 않는다.
4. 릴리스 워크플로가 같은 SHA의 CI를 다시 확인하고 5종 바이너리를 빌드한다.
5. 설치 파일을 모두 모아 체크섬을 만들고 draft에 업로드한다. 업로드한 파일을 다시 내려받아 검증한 뒤에만 정식 릴리스로 공개한다.

이미 공개된 버전은 덮어쓰지 않는다. 수정이 필요하면 새 버전을 만든다. 일시적인 아티팩트 다운로드만 최대 3회 재시도하며, 테스트 실패를 자동 재시도로 덮지 않는다.

이 절차는 알려진 실패 상태에서 배포를 시작하는 일을 막는다. 신규 결함이나 외부 서비스 장애까지 없애지는 않으며 실패 알림은 유지한다.

## 검증

- `python -m unittest discover -s .github/tests`
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`
- 워크플로 변경은 actionlint로 검사한다.
- 릴리스 파이프라인 변경만으로 새 제품 버전을 자동 배포하지 않는다.
