## 수정 목적

같은 신원의 대화형 수신자와 데몬이 경쟁해 메시지가 다른 실행체로 전달되는 문제를 고친다.
웹 대화 자동 주입은 범위에 포함하지 않는다. 원격 MCP는 CLI에서도 사용할 수 있으므로
수신 점유 검사는 WS·HTTP·원격 MCP에 공통 적용한다. 규약의 진실은 PROTOCOL.md 2.2다.

## 우선순위와 동작

1. 단일 수신 점유를 모든 전송 경로에 적용한다. 명시적 연결은 기존 takeover/reject 정책을
   따르고, 데몬은 최초 JOIN부터 기존 소비자를 존중한다. 점유 조회 실패는 빈 자리가 아니다.
2. 이전 연결의 버퍼·확인 토큰을 폐기한다. 연결마다 반복될 수 있는 서버 전달 번호와
   프로세스 내 확인 토큰을 분리한다. 데몬은 wake 전에 확인 유보 토큰을 서버 전달 번호로
   변환해 RESERVE한다. 예약 OK부터 착수 ACK/RELEASE까지 다른 세션의 인계는 대기한다.
   새 점유가 먼저 성립하면 예약은 거부된다. 연결 장애를 걸친 exactly-once 실행은 아니며
   예약 응답 유실 시 시작하지 않고 연결을 닫는다. at-least-once 중복 제거는 유지한다.
3. 점유를 잃은 수신자의 전달·ACK·presence 쓰기를 막는다. 일반 대화형 클라이언트는
   축출 후 자동으로 자리를 되찾지 않는다. 대기형 어댑터는 자리가 빌 때까지 standby다.
4. 충돌은 `agent/session-conflict`, 단절은 실제 종료 원인과 함께 드러낸다.
   `wait_for_message`는 이를 정상 타임아웃으로 돌려주지 않는다.
5. 서버 발급 `receiver.session_id`와 전달의 `meta._brv_receiver`로 수신 귀속을 비교한다.
   로컬 MCP 상태는 해당 연결의 ID를 제공한다. 인증 토큰·OS PID와 혼동하지 않는다.

`daemon-state.json`의 standby는 **데몬의 상태**다. 대화형 연결이 살아 있는 동안
데몬이 standby인 것은 정상이다. 에이전트의 실제 점유는 서버 PRESENCE의 receiver로 확인한다.
회신은 `correlation_id`로 요청을 식별하고 에이전트의 현재 수신자에게 이어진다.

## 검증

- 로컬 회귀: 축출 직전 버퍼가 wake에 쓰이지 않는지, 충돌이 즉시 노출되는지,
  재접속으로 같은 서버 번호가 반복돼도 이전 확인 토큰이 거부되는지 검증한다.
- 서버 통합 회귀: WS 점유 중 HTTP·백그라운드 JOIN 거부, takeover 이후 presence 유지,
  WS↔원격 MCP 경쟁 및 명시적 재연결을 검증한다.
- 공개 리포는 OS 3종 fmt/clippy/test, 서버는 격리된 테스트 인프라에서 회귀를 실행한다.
  사용자 CLI 설치·바인딩·실제 대화에는 테스트를 주입하지 않는다.

호환 배포에는 서버와 brv 양쪽 수정이 필요하다. 이전 서버는 새 standby 요청을 강제하지
않으므로 클라이언트만 갱신한 결과를 이 결함의 완료 검증으로 삼지 않는다.

## 설계 검토 보완

- HTTP ACK는 재시작 시 seq가 반복되어도 구분되도록 전달의 `_brv_delivery_id`를
  `ACK_DELIVERY` body에 돌려준다. 구형 HTTP ACK와 잘못된 증명은 항목을 소비하지 않는다.
  WS ACK는 기존 형식이다. HTTP 직접 연동 클라이언트와 서버는 함께 갱신해야 한다.
- WS RESERVE/RELEASE는 모델·OS에 독립적인 착수 인계 제어다. 실제 프로세스 실행과
  실행 권한은 여전히 로컬 어댑터가 소유하며 외부 메시지는 권한을 넓히지 못한다.
- 프로토콜 presence와 관리 화면의 상태 판정을 통합한다. 점유 임대가 유효한 동안
  오래된 기록 때문에 활성 대기를 idle로 표시하지 않는다. last_seen을 조작하지 않는다.

### 검증 결과 — 2026-09-09

Windows GNU 환경에서 공개 저장소 118건과 서버 57건의 전체 회귀가 통과했다.
양쪽 `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`를 수행했다.
서버 통합 테스트는 전용 테스트 인프라를 명시해 실행했다. 재시작 ACK 증명, 잘못된 예약,
배치 일부 ACK 중 인계 대기, 착수 실패 해제, 연결 종료 해제, 예약 응답 유실,
관리 API 두 경로의 MCP 임대/기록 만료 판정을 포함한다.
macOS·Linux CI와 사용자 실제 CLI 실측, 운영 배포는 이번 로컬 검증 결과에 포함하지 않는다.
